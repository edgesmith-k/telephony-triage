3검증

이 절에서 알 수 있는 것: 검증 관련 용어

용어뜻
fixture원인마다 붙인 마스킹된 최소 로그. 회귀 테스트 입력
회귀·검증 모드fixture 전체 범위, 모든 원인 독립 평가로 판정하는 모드
R1 파서새 규칙이 쓰는 태그·이벤트가 이 원인의 기준 로그에서 실제로 뽑히나
R2 양성기준 로그에서 이 원인만 C=1, 다른 원인은 C=0인가
R3 음성정상 로그·다른 원인 로그·고친 뒤 로그를 잘못 잡지 않나
R4 교차 회귀이슈 DB 모든 fixture의 기대 결과가 그대로인가. 실패하면 push 차단
R5 이벤트 변화파서 규칙을 바꿀 때 기존 이벤트가 사라지거나 바뀌지 않나. 바뀌면 메인테이너 승인 필요
R6 추가 표본사용자가 준 다른 로그로 확인(선택). 실패해도 진행 여부는 사용자가 고름
skipped검증을 못 돌림. 통과가 아니며 리뷰 대상
also_allowed한 fixture에서 다른 유형의 원인도 C=1이어도 된다는 허용. 실제로 두 현상이 있을 때만
수정 상태open · fix-submitted · fixed · wont-fix · not-a-bug. fixed는 verify-fix 통과로만
해결책 검증해결책이 효과 있었는지. 미검증 / 검증됨(근거 필수)
