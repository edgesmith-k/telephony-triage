분석 스킬의 "규칙 제안"은 어떻게 처리되나

분석 스킬이 "이런 규칙을 추가하면 좋겠다"고 제안하면, 이제 흘려보내지 않고 분류를 정한 뒤 사용자에게 한 번 물어서 반영합니다. 아무것도 자동으로 바뀌지 않습니다.

무엇이 바뀌었나

전
  1. 분석 스킬이 로그를 보고 의견을 낸다
  2. 의견이 리포트에 적힌다
  3. 규칙 제안이 있어도 리포트 글로 끝난다
후
  1. 분석 스킬이 로그를 보고 의견을 낸다
  2. 의견이 리포트에 적힌다
  3. 분류를 정한 뒤 "이 제안 받을까요?"라고 묻는다 (여러 개 고를 수 있음)

전체 흐름에서 어디쯤인가

윗줄은 모든 기록이 지나는 이슈 DB 경로, 아랫줄은 규칙 제안이 있을 때만 생기는 분석 스킬 경로입니다. 점선 테두리는 사람이 고르는 곳입니다.

받겠다고 고르면, 제안 종류에 따라 이렇게 됩니다

① 이슈 DB 규칙 제안

예: "이 로그 줄을 이벤트로 잡는 규칙을 추가하자"

초안 보여 줌→사용자 승인→자동 검증→확인 화면→PR

평소 이슈 기록과 같은 길을 탑니다. push 확인 화면에서 "push하고 바로 병합"을 고르면 본인이 바로 합칩니다. 다만 파서 규칙(parser-rules/) 같은 메인테이너 경로 변경은 메인테이너 리뷰를 거칩니다.

② 분석 스킬 개선 제안

예: "점검 목록에 설정 화면 확인을 추가하자"

수정 파일(.patch) 생성→내용 보여 줌→"바로 적용할까요?"→실행 허가→스킬 소스에 적용

스킬 소스 폴더를 설정해 두면(analyzers.<카테고리>.source) 수정 내용을 보여 주고 물은 뒤 그 폴더에 바로 적용합니다. 커밋·push는 하지 않으니 확인하고 직접 올립니다. 설정이 없으면 수정 파일만 남기고 반영은 본인이 판단합니다. 설치된 플러그인 폴더의 스킬은 어느 쪽이든 고치지 않습니다.

알아 둘 것

  • 묻는 건 한 번뿐이고 여러 개를 함께 고를 수 있습니다. 그냥 넘기면 "받지 않음"으로 처리해 규칙이 저절로 늘지 않습니다(규칙 추가는 사용자 확인 후에만). 안 받으면 예전과 똑같습니다.
  • 분석 스킬이 제안을 내지 않으면 이 질문도 나오지 않습니다.
  • 수정 파일에는 마스킹된 값만 들어갑니다. 마스킹 때문에 스킬 소스에 적용이 안 될 것 같으면 파일을 만들지 않고 메모로만 알려 줍니다.
  • 바로 적용은 스킬 소스가 git 저장소이고, 바꿀 파일에 커밋하지 않은 수정이 없고, 수정 파일이 그대로 맞고, 화면에 다 보일 만큼 작을 때(200줄·12KB 이하)만 합니다. 아니면 이유를 알려 주고 수정 파일만 남깁니다. 마스킹으로 바뀐 줄이 있으면 placeholder가 소스에 들어간다고 미리 알려 줍니다.
자세히 (분석 스킬 담당자·개발자용)
  • 분석 스킬은 결과 끝에 아래 형식으로 제안을 적습니다(16-existing-assets.md §16.5). 파일은 바꾸지 않습니다.
규칙 제안:
- [이슈 DB] add-parser-rule file=extractors.yaml rule=<태그·패턴 → 이벤트> — 근거: <마스킹된 로그 줄>
- [이슈 DB] update-signature cause=DATA-001-01 must_event 추가 — 근거: <로그 줄·이유>
- [스킬] references/DATA-001.md에 점검 순서 추가 — 근거: 이번 이슈에서 확인 순서가 빠짐
  • [이슈 DB] 줄: db-authoring.md 점검을 거친 op 초안 → 승인분만 plan.json → db_verify rules → push 승인 → PR.
  • [스킬] 줄: JOB/skill-suggestions/<스킬>.patch(unified diff, 스킬 폴더 기준 경로). 스크립트 skill_patch.py가 만들고 마스킹한 뒤 스킬 폴더 사본에 git apply --check가 통과할 때만 안내 줄을 냅니다. 안내 줄은 표시 보조 hook이 화면에 꼭 보이게 합니다(절차 reference/skill-patch.md).
  • 바로 적용: source가 있으면 같은 스크립트가 적용 가능성을 미리 보고 patch 전문과 sha256을 냅니다. "적용"이면 skill_patch.py <KEY> --name <스킬> --apply --sha <H>가 보인 patch(sha256 대조)만 그 저장소 워킹 트리에 git apply합니다(index·커밋·push 없음, guard 규칙 12가 권한을 묻습니다, 16-existing-assets.md §16.5.1).
  • patch는 작업이 끝나도 남고, db_pr cleanup --older-than으로 오래된 작업 폴더를 지울 때 함께 지워집니다.
  • 검증: eval 71이 [스킬] 갈래(patch만)를 실행합니다(10/21 사외 통과). 바로 적용(source)과 [이슈 DB] 갈래를 실행하는 eval은 아직 없습니다(단위 테스트 tests/test_skill_patch.py).
