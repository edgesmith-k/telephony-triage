분석 스킬의 "규칙 제안"은 어떻게 처리되나

분석 스킬이 "이런 규칙을 추가하면 좋겠다"고 제안하면, 이제 흘려보내지 않고 분류를 정한 뒤 사용자에게 한 번 물어서 반영합니다. 아무것도 자동으로 바뀌지 않습니다.

무엇이 바뀌었나

전
  1. 분석 스킬이 로그를 보고 의견을 낸다
  2. 의견이 리포트에 적힌다
  3. 규칙 제안이 있어도 리포트 글로 끝난다
후
  1. 분석 스킬이 로그를 보고 의견을 낸다
  2. 의견이 리포트에 적힌다
  3. 분류를 정한 뒤 "이 제안 받을까요?"라고 묻는다 (기본은 아니오)

받겠다고 고르면, 제안 종류에 따라 이렇게 됩니다

① 이슈 DB 규칙 제안

예: "이 로그 줄을 이벤트로 잡는 규칙을 추가하자"

초안 보여 줌→사용자 승인→자동 검증→PR

평소 이슈 기록과 같은 길을 탑니다. 리뷰어가 PR을 합쳐야 이슈 DB에 들어갑니다.

② 분석 스킬 개선 제안

예: "점검 목록에 설정 화면 확인을 추가하자"

수정 파일(.patch) 생성→담당자에게 전달

분석 스킬은 다른 팀 소유라 직접 고치지 않습니다. 담당자가 수정 파일을 보고 반영합니다.

알아 둘 것

  • 묻는 건 한 번뿐이고 기본은 "아니오"입니다. 안 받으면 예전과 똑같습니다.
  • 분석 스킬이 제안을 내지 않으면 이 질문도 나오지 않습니다.
  • 수정 파일에는 마스킹된 값만 들어갑니다. 마스킹 때문에 담당자 쪽에서 적용이 안 될 것 같으면 파일을 만들지 않고 메모로만 알려 줍니다.
자세히 (분석 스킬 담당자·개발자용)
  • 분석 스킬은 결과 끝에 아래 형식으로 제안을 적습니다(16-existing-assets.md §16.5). 파일은 바꾸지 않습니다.
