위치저장되는 것보존

Jira 요약·설명·댓글 원문과 사람 이름은 팀 DB·리포트·PR 어디에도 넣지 않습니다.

3마스킹 항목

이 절에서 알 수 있는 것: 자동으로 가리는 값

항목바뀌는 모양
IMSI · IMEI · ICCID<IMSI#n> <IMEI#n> <ICCID#n>
IMEI 변형 (구분자 -·공백, imeisv, 문맥 없는 NN-NNNNNN-NNNNNN-N + Luhn)<IMEI#n> (같은 IMEI의 표기 변형은 같은 번호)
EID (eUICC, eid 키 32자리)<EID#n>
SUPI · SUCI · TMSI · GUTI<SUPI#n> 등
전화번호, tel: URI<MSISDN#n>
SIP URI · IMPU · IMPI (사용자 부분)<IMPU#n> <IMPI#n>
Cell ID · TAC · CI · PCI 등<CELL#n>
IP · MAC · 이메일 (버전 문자열 앞 IPv4는 두기, MAC은 - 6옥텟·키 문맥 12 hex 포함)<IP#n> <MAC#n> <EMAIL#n>
GPS 좌표 (lat·lon 키, gps 좌표 쌍)<GEO#n>
장치 serial (ro.serialno·serialno 키, sn·serial은 영문+숫자 혼합만)<SERIAL#n>
자격 증명 (SIP response·nonce, AKA 값·Ki·OPc, password·token·key, pin·puk 숫자 4~8자리, Bearer·JWT)<CRED#n>

같은 파일 안에서 같은 값은 같은 번호로 바뀌어 비교 관계가 남습니다. 빌드 번호·시각을 잘못 가리지 않도록 문맥 기반 탐지를 우선합니다. 오탐 예외는 팀 설정(메인테이너 리뷰)이고, 너무 넓은 예외는 검사가 거부합니다. 이미 마스킹된 입력에 다시 적용해도 결과가 같습니다.

한계사람 이름은 정해진 형식이 없어 패턴으로 잡지 못합니다. 그래서 Jira에서 저장하는 정보 자체를 최소화했습니다.

4위협과 대응

이 절에서 알 수 있는 것: 무엇을 걱정하고 어떻게 막나

위협대응남는 위험
개인정보가 팀 DB에 들어감마스킹, 커밋 전 개인정보 검사(Claude hook + git pre-commit), 확인 화면이름 등 패턴 없는 값 → 저장 최소화
개인정보가 Claude 대화에 들어감Jira 원문 격리, 로그 원문 통째로 읽기 차단Read 도구 통독은 지침으로만 제한(S-2 뒤 대책)
Jira가 바뀜허용 목록 읽기 도구만 통과, 그 밖은 거부. 설정 전이라도 이름에 jira·atlassian이 든 서버의 쓰기 도구는 거부. 의존성이 없어 판정을 못 하면 MCP 도구 전부 거부이름에 그 단어가 없는 미설정 서버는 설정 후에만 보호
Jira 본문의 지시 주입원문을 대화에 넣지 않음, 본문 문장은 데이터로만 취급, 주입 eval 59·60실제 환경 측정은 S-2
리뷰 없는 main 변경서버 브랜치 보호 + CODEOWNERS 필수 리뷰, main push 차단 hook서버 설정이 없으면 PC 장치만 남음
승인과 다른 내용 push승인 지문 대조, pre-push 검사—
이슈 DB 원격을 Claude가 직접 바꿈이슈 DB 대상 gh 쓰기·GitHub MCP 쓰기는 승인 질문, PR 머지는 거부curl로 REST 직접 호출은 못 봄 → 서버 보호가 최종
내 clone이 바뀜Claude의 파일 쓰기와 clone 본체의 브랜치·파일 변경 Bash 명령 거부복잡한 명령 형태는 최선 노력
검사 우회--no-verify·hook 경로 변경 차단복잡한 명령 형태는 최선 노력 → 서버 보호가 최종
사내 정보가 사외로경계 검사(check_boundary.py), 사내 값은 정해진 경로에만, 사외로는 사람이 쓴 문장만—
