후보와 근거를 제시하고, 최종 판단은 엔지니어가 합니다.

01 / 분석

반복 이슈는 예전 원인부터 봅니다

로그를 등록된 원인 규칙과 대조합니다. 후보·근거·다음 확인을 함께 보여줍니다.

02 / 공유

찾은 원인을 팀이 함께 씁니다

원인과 해결책, 관련 이슈를 이어 둡니다. 다음 담당자가 찾아 쓸 수 있습니다.

03 / 품질

새 규칙은 검사를 거쳐 쌓습니다

예시 로그와 기존 사례로 검사합니다. 검사를 통과한 PR만 팀 이슈 DB에 들어가고, 공통 규칙 변경은 메인테이너가 리뷰합니다.

같은 지식으로 회귀 감시·릴리스 확인·대량 분류까지 넓혀 쓸 수 있습니다(후보, 파일럿 결과를 보고 고름).

분석에서 지식 축적까지, 하나의 흐름

  1. 1. 이슈와 로그 전달Jira 키 · 로그 파일 경로
  2. 2. 후보와 근거 확인규칙 매칭 · 분석 리포트
  3. 3. 사람이 판단·승인분류 확정 · 변경 내용 검토
  4. 4. 팀 지식으로 축적PR 병합 · 다음 분석에 재사용
