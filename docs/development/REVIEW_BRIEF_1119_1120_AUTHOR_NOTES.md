## 3. 작성자가 아는 한계 (PR #170 본문 등)

- 재시험이라는 말 없이 재시험한 경우, 옛 회차 단서가 이번 회차로 잡혀 틀리게 채택될 수 있다.
- 실패를 문장으로만 쓰고 다른 token을 "참고"로 적으면, 그 token 사건의 원인이 채택될 수 있다.
- 같은 실패를 두 줄로 인용하면(한 실패가 사건 둘로 잡히는 로그) 보류된다.
- 플러그인이 Jira MCP 응답을 직접 받는 경로에서, 코멘트 전체 수(total)나 작성 시각(created)이 없으면 자동 추출이 꺼진다. 포털 경로는 다르다: 포털이 total을 늘 채우고 created 없이 본문만 넘기므로, 플러그인은 받은 순서를 믿고 추출한다.
- 원인이 다른 두 사건이 몇 ms 차로 합쳐지면 한쪽만 원인이 있어도 보류한다(작성자 캡처에서 4건 손실로 적힘).
